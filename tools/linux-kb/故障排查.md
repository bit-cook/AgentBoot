# Linux 常见问题修复手册（按症状查）

## 一、SSH 登录不上
```bash
服务器侧（有控制台时）：
1. systemctl status sshd                     # 服务活着吗
2. ss -lntp | grep :22                       # 在监听吗
3. journalctl -u sshd -n 50                  # 报错：密码错？密钥权限？超限？
4. 密钥登录被拒：~/.ssh 权限必须 700/600；ls -ld 检查家目录不能 777
5. 防火墙/安全组：firewall-cmd --list-all；云服务器看控制台安全组
6. /etc/hosts.deny、fail2ban（iptables -L | grep f2b）可能封了 IP
客户端侧：ssh -v user@host 看卡在哪一步
```

## 二、服务/网站起不来
```bash
1. systemctl status <svc> && journalctl -u <svc> -n 50
2. 端口冲突：ss -lntp | grep :80 → 换端口或杀进程
3. 配置语法：nginx -t / apachectl -t / 应用自身 config check
4. 权限：应用用户能否读配置、写日志/上传目录（ls -l 逐级看）
5. SELinux：getenforce；临时 setenforce 0 验证；restorecon -Rv 恢复标签
6. 磁盘满也会导致起不来：df -h
7. 依赖没起：systemctl list-dependencies <svc>
```

## 三、网络不通
```bash
1. ip a                     # 网卡有 IP 吗（dhcp 失败？dhclient -v eth0）
2. ip r                     # 有 default 网关吗
3. ping 网关 → ping 223.5.5.5 → ping baidu.com（定位是链路还是 DNS）
4. DNS 坏：echo "nameserver 223.5.5.5" > /etc/resolv.conf
5. 出站被墙/被防火墙挡：iptables -L -n；firewall-cmd --list-all
6. MTU 问题（能 ping 通但大包丢）：ping -M do -s 1400 host
```

## 四、CPU 100%
```bash
1. top -bn1 -o %CPU | head -15          # 找进程
2. ps -mp <PID> -o THREAD,tid,time      # 找线程；printf "%x\n" <tid> 转16进制
3. 若是 java：jstack <PID> | grep -A 20 <tid的16进制>
4. 挖矿病毒特征：进程名乱码、/tmp 下的可执行、异常外联 → ss -lntp | grep <PID>
   应急：kill -9 <PID>；查 cron：crontab -l、/etc/cron*、systemctl list-timers
```

## 五、内存不足 / OOM
```bash
1. free -h                                   # available 很低？
2. journalctl -k | grep -i "out of memory"   # 确认 OOM killer 杀了谁
3. ps aux --sort=-%mem | head                # 内存大户
4. 应急：重启大户服务；增加 swap（见磁盘篇）
5. 限制：systemd unit 加 MemoryMax=1G；容器加内存限额
```

## 六、磁盘满（最常见，详见磁盘篇）
```bash
df -h → du -xh --max-depth=1 / | sort -rh | head
journalctl --vacuum-size=100M；docker system prune；lsof | grep deleted
```

## 七、文件删了空间没释放
```bash
lsof | grep deleted            # 进程仍持有句柄
systemctl restart <对应服务>    # 或 kill 进程后空间立即释放
```

## 八、时间不对
```bash
timedatectl                          # 看时区与同步状态
timedatectl set-timezone Asia/Shanghai
timedatectl set-ntp true             # 开启 NTP
chronyc sources -v                   # chrony 同步源
# 时间漂移会导致 https 证书校验失败、API 鉴权 401
```

## 九、证书报错（curl: certificate verify failed）
```bash
date                              # 多数是系统时间错
curl -vI https://site             # 看具体哪一环
update-ca-trust / update-ca-certificates   # 更新根证书
# 自签证书：curl -k 跳过（仅调试）
```

## 十、中文乱码
```bash
locale                            # 看当前编码
localectl set-locale LANG=zh_CN.UTF-8   # 或 en_US.UTF-8
export LANG=zh_CN.UTF-8           # 会话级
ls 乱码文件用 inode 删：ls -i；find . -inum <号> -delete
```

## 十一、yum/apt 报错
```bash
apt：sudo apt update 看具体 404/超时 → 换源（见软件包篇）
yum：yum clean all && yum makecache；检查 /etc/yum.repos.d/ 与 epel 匹配系统版本
GPG 错误：--nogpgcheck 仅调试用；正规做法导入对应 key
```

## 十二、进程无法杀死 / 僵尸进程
```bash
kill -9 <PID>                    # 还不行 → 通常是不可中断 IO（D 状态）
ps -o stat= -p <PID>             # D 状态：等存储恢复，检查 IO/网络存储
僵尸（Z）：杀其父进程；ps -o ppid= -p <PID> 查父进程
```
