# Linux 用户与权限

## 用户与组
```bash
id                       # 当前用户身份
whoami && who            # 我是谁 / 谁在线
useradd -m -s /bin/bash dev    # 建用户带家目录
passwd dev               # 设密码
usermod -aG wheel dev    # 加入 wheel（RHEL sudo 组）；Ubuntu 是 sudo 组
groups dev               # 查所属组
su - dev                 # 切换用户
sudo -u www ls /home/www # 以指定用户执行
userdel -r dev           # 删用户连带家目录（危险）
```

## 文件权限
```bash
ls -l file
# -rw-r--r-- 1 root root  → 属主 rw，组 r，其他 r
chmod 755 script.sh      # rwxr-xr-x：目录/可执行常用
chmod 644 file.conf      # rw-r--r--：配置文件常用
chmod +x script.sh       # 加执行位
chown user:group file    # 改属主属组
chown -R www:www /var/www   # 递归（谨慎）
umask                    # 默认权限掩码（022 → 新文件 644）
```

## Permission denied 排查套路
```bash
1. ls -l 报错路径的每一级目录     # 父目录也需要 x 权限
2. id                            # 确认自己在哪个组
3. 是不是 SELinux？ls -Z /etc/nginx；getenforce
   恢复上下文：restorecon -Rv /var/www
4. 只读文件系统？mount | grep " / "   # ro 就不是权限问题
5. 临时验证：sudo <命令> 能跑 → 就是普通用户权限不足
```

## sudo 配置
```bash
visudo                   # 唯一正确的编辑方式（语法校验）
# 允许 dev 免密执行所有命令：
dev ALL=(ALL) NOPASSWD: ALL
# 只允许重启 nginx：
dev ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
sudo -l                  # 查看自己可执行的 sudo 命令
```

## SSH 密钥登录
```bash
ssh-keygen -t ed25519            # 生成密钥对
ssh-copy-id user@host            # 推送公钥到服务器
# 手动：公钥内容追加到服务器的 ~/.ssh/authorized_keys
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys   # 权限不对会拒绝登录！
```
